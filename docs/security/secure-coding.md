# 시큐어코딩 가이드 적용 현황

기준 문서

- 행정안전부·KISA 「소프트웨어 개발보안 가이드」(2021.12.29) 구현단계 보안약점 7분류 49항목
- 「소프트웨어 보안약점 진단가이드」(2021): 진단 절차, 증적, 재검사
- 「Python 시큐어코딩 가이드」: 경로 조작, OS 명령, 역직렬화 항목
- 「AI 보안 안내서」: LLM 입력·출력 통제
- 「제로트러스트 가이드라인 2.0」: 최소권한, 단계별 같은 격리 정책
- 「SW 공급망 보안 강화 로드맵」(2026.6): 무결성 검증, 구성요소 관리(→ [supply-chain.md](supply-chain.md))

위협 모델은 이렇다. 대상 프로젝트 소스, 빌드 스크립트(CMake·Bazel), 프로필, 코퍼스, LLM 응답은
모두 **비신뢰 입력**으로 본다. 이 값이 파일 경로, 실행 환경, 외부 전송으로 흘러가는 지점마다
`logosfuzz/common/security.py` 의 공통 함수를 거치게 했다.

| 함수 | 막는 것 | 대응 항목 |
| --- | --- | --- |
| `safe_component` / `safe_join` | `..`, 절대경로, 드라이브/UNC 경로, 역슬래시, symlink 를 통한 허용 루트 이탈 | 입력검증 3 (CWE-22) |
| `minimal_env` | 빌드·하네스 실행 때 부모 환경(API 키, 클라우드 자격증명)이 상속되는 것 | 보안기능 3·5, 에러처리 1 (CWE-526) |
| `redact_secrets` / `prepare_outbound` | 로그, 프롬프트, 외부 LLM 전송에 비밀값이 실리는 것 | 에러처리 1, 보안기능 5 (CWE-532) |
| `cap_text` / `_BoundedLines` | 출력 폭주로 메모리·디스크가 고갈되는 것 | 코드오류 2 (CWE-400) |

## 보완 항목(F01~F10)과 이번 수정

판정 기준: **조치** = 이번 커밋에 코드와 회귀 테스트가 있음. **부분** = 일부만 조치했고 남은 범위를
적어 둠. **미조치** = 설계 결정이 필요해 남겨 둠. 회귀 테스트는 `tests/test_security_hardening.py` 에 있다.

| ID | 내용 | 판정 | 이번 수정 / 남은 범위 |
| --- | --- | --- | --- |
| F01 | 미신뢰 프로젝트 빌드가 호스트에서 실행됨 | 부분 | 빌드 환경을 허용 목록으로 다시 만들었다(비밀값 차단). 기본 시간 상한은 3600초로 두었다. **남은 범위:** CMake configure/build 를 격리 컨테이너에서 실행하는 실행기, 원본을 읽기 전용으로 보존한 scratch 빌드. 외부 제출물을 받기 전에 필요하다 |
| F02 | 재생·커버리지 단계의 격리가 퍼징 단계보다 약함 | 조치(이 브랜치 범위) | 커버리지 도구 컨테이너에 퍼징과 같은 정책을 적용했다(`--cap-drop ALL`, `no-new-privileges`, 메모리·CPU·PID 상한, 호스트 uid). 호스트 실행기는 최소 환경으로 바꾸고 600초 상한을 두었다. 보고서가 지적한 `generic_run.py` 의 corpus replay 경로는 이 브랜치에 없으므로, 병합할 때 같은 `_docker_prefix` 를 써야 한다 |
| F03 | 빌드·로컬 실행에 비밀 환경변수가 상속됨 | 조치 | `CMakeAdapter`, `BazelAdapter`, `BazelCompiler`, `SubprocessCompiler`, `validation`, `regression`, `docker_runner` 기본 실행기, 커버리지 실행기를 모두 `minimal_env` 로 바꿨다. LLM 키는 LLM 클라이언트만 읽는다. 운영자는 `LOGOSFUZZ_ENV_PASSTHROUGH` 로 변수를 추가할 수 있지만, 이름이 비밀처럼 보이는 변수는 이 설정으로도 넘어가지 않는다 |
| F04 | 경로 조작과 광범위 삭제 | 조치 | Bazel `package_dir` 검증, BUILD 문자열 삽입 차단, 사용자 BUILD 덮어쓰기 거부, `remove()` 를 `rmtree` 대신 manifest 에 적힌 파일만 지우도록 바꿨다. CMake 하네스·바이너리 경로, `SubprocessCompiler` 의 `logic_group`, 실행 로그·커버리지 경로의 그룹 이름도 검증한다 |
| F05 | 단계별 시간·출력 상한 부족 | 조치 | 출력 큐 크기 제한(배압), 한 줄 64KB 제한, 앞 2,000줄과 뒤 20,000줄만 보존한다. 모니터는 버린 줄도 모두 본다. 새 세션으로 띄워 타임아웃 때 프로세스 그룹을 통째로 종료한다. CMake 와 커버리지 도구에 기본 상한을 두었다. **남은 범위:** 디스크 quota, 코퍼스·JSON 개수 상한 |
| F06 | LLM 입력의 비밀정보·지시 오염 | 부분 | 외부 전송 전에 마스킹과 6만 자 상한을 적용했다(`OpenAILLMClient`, `llm_harness_generator`). 시스템 프롬프트에 비신뢰 데이터 분리 원칙을 넣었고, 20만 자를 넘는 응답은 코드로 받지 않는다. **남은 범위:** 프로젝트별 외부 전송 허용 여부, 생성 코드 SAST gate. 프롬프트 문구만으로 주입을 모두 막을 수는 없다 |
| F07 | 승인·로그 저장 실패 처리와 다중 프로세스 무결성 | 조치 | HITL 저장소에 `flock` 프로세스 락을 걸고, 디스크 최신본에 병합해 쓴다. 임시 파일은 고유 이름에 0600 권한, fsync 후 교체한다. 저장 실패 예외는 그대로 올린다. 실행 로그 저장 실패는 `GroupResult.log_error` 와 `evidence_complete=False` 로 표시하고, 커버리지 원문 저장 실패는 경고 로그를 남긴다. **남은 범위:** 승인자 인증, 변경 해시 결합 |
| F08 | 다운로드 무결성 검증이 선택 사항이었음 | 조치 | Bazelisk sha256 검증을 필수로 바꿨다(amd64·arm64). 값이 비거나 다르면 빌드가 실패한다. 베이스 이미지는 digest 로 고정했다. **남은 범위:** Bazelisk 가 받는 Bazel 본체와 외부 rule |
| F09 | 의존성·SBOM·CI 보안 검사 | 부분 | `.github/workflows/security-checks.yml` 을 추가했다. Bandit 은 medium 이상이면 실패하고, pip-audit 는 취약점이 있으면 실패하며, 결과 원문은 아티팩트로 남긴다. CI 권한은 `contents: read` 로 줄였다. **남은 범위:** lock+해시, SBOM, Action SHA 고정, C/C++ 정적 분석 |
| F10 | 미완료 검사가 성공으로 해석될 위험 | 부분 | CMake 캐시 키에 소스 commit, 컴파일러, 플래그, configure 인자, 라이브러리 목록 해시를 넣었다. 설정이 바뀌면 다시 빌드한다. 로그 증적 상태는 F07 에서 처리했다. **남은 범위:** 리포트의 pass/fail/incomplete/not_applicable 상태 구분 |
| O01 | 공유 Notion 의 평문 자격증명 | 코드 외 | 저장소 추적 파일에 비밀값 형식이 없는지 회귀 테스트로 검사한다(`test_no_secret_like_values_are_committed`). Notion 비밀번호 교체·삭제는 계정 담당자가 해야 한다 |

### 정적 분석 결과(이 커밋 기준)

- Bandit(1.8.6, `-x '*/tests/*'`): 수정 전 medium 이상 7건이었다. sha1/md5 3건, 예측 가능한 `/tmp` 3건, XML 파싱 1건이다.
  - 해시 3건은 클러스터·중복 판별용 지문이라 `usedforsecurity=False` 를 명시했다. 다이제스트 값은 바뀌지 않는다.
  - 호스트 `/tmp/seed` 는 출력 디렉터리 아래 시드로 바꿨다.
  - 컨테이너 전용 `/tmp`, 가짜 경로 문자열, 자체 실행한 `bazel query` XML 은 사유를 주석에 적고 `# nosec` 로 남겼다.
  - 수정 후 medium 이상은 0건이다. low 41건은 대부분 `subprocess` 사용 알림(B603/B404)이다. 모두 argv 배열 호출이고 `shell=True` 는 없다.
- pip-audit(requirements.txt): 알려진 취약점 0건.
- 경고 건수는 보안약점 건수와 같지 않다. 위 판정은 수동 확인을 거친 결과다.

## 구현단계 49개 보안약점 적용 표

적용 = 해당 기능이 있고 통제를 확인함. 해당 없음 = 그 기능이 없음(사유 기재). 생성 C/C++ 하네스의
메모리 항목은 Python 코드가 아니라 퍼저가 대상 코드에서 찾는 결함 유형이라, 하네스 자체는 컴파일
strict 경고와 sanitizer 로 검증한다.

| 분류 | 번호 | 항목 | 상태 | 근거 |
| --- | --- | --- | --- | --- |
| 입력데이터 검증 | 1 | SQL 삽입 | 해당 없음 | DB 를 쓰지 않음 |
| | 2 | 코드 삽입 | 적용 | `eval`/`exec`/`pickle` 미사용. LLM 이 만든 코드는 격리 컨테이너에서만 실행(F06 남은 범위 참고) |
| | 3 | 경로 조작 및 자원 삽입 | 적용 | `safe_join`/`safe_component`(F04) |
| | 4 | 크로스사이트 스크립트 | 부분 | HTML 보고서가 escaping·숫자 변환을 사용(`reporting/web/report.js`). 비신뢰 JSON 으로 배포 환경을 검증하는 일은 남음 |
| | 5 | 운영체제 명령어 삽입 | 적용 | 모든 호출이 argv 배열이고 `shell=True` 없음. 컨테이너 셸 인자는 `shlex.quote`, 그룹 이름은 셸에 들어가기 전에 검증 |
| | 6 | 위험한 형식 파일 업로드 | 해당 없음 | 업로드 기능 없음(웹 UI 를 병합하면 재평가) |
| | 7 | 신뢰되지 않는 URL 자동접속 | 해당 없음 | 리다이렉트 기능 없음 |
| | 8 | 부적절한 XML 외부 개체 참조 | 적용 | 표준 ElementTree 는 외부 엔티티를 해석하지 않음. 입력은 자체 실행한 bazel 출력 |
| | 9 | XML 삽입 | 해당 없음 | XPath/XQuery 를 외부 입력으로 만들지 않음 |
| | 10 | LDAP 삽입 | 해당 없음 | LDAP 미사용 |
| | 11 | 크로스사이트 요청 위조 | 해당 없음 | 상태를 바꾸는 웹 엔드포인트 없음 |
| | 12 | 서버사이드 요청 위조 | 부분 | LLM endpoint(`base_url`)는 운영 설정 전용이고 사용자 입력으로 바꿀 수 없음. 바꿀 수 있게 하려면 allowlist 가 필요 |
| | 13 | HTTP 응답분할 | 해당 없음 | HTTP 서버 없음 |
| | 14 | 정수형 오버플로우 | 해당 없음(Python) | 생성 C 하네스는 `-Werror=` 정수 변환 경고와 UBSan 으로 검증 |
| | 15 | 보안기능 결정에 쓰이는 부적절한 입력값 | 부분 | HITL 승인이 인증된 사용자와 아직 결합되어 있지 않음(F07 남은 범위) |
| | 16 | 메모리 버퍼 오버플로우 | 해당 없음(Python) | 하네스는 ASan 으로 실행 |
| | 17 | 포맷 스트링 삽입 | 해당 없음(Python) | 하네스 대상 결함 유형. 하네스 자체의 포맷 경고 강화는 미적용 |
| 보안기능 | 1 | 적절한 인증 없는 중요 기능 허용 | 부분 | 단일 사용자 CLI 가정. 다중 사용자 서비스라면 인증이 필요 |
| | 2 | 부적절한 인가 | 부분 | 위와 같음 |
| | 3 | 중요한 자원에 대한 잘못된 권한 설정 | 적용 | HITL 저장 파일과 락 파일 0600, 컨테이너 `--cap-drop ALL`·`no-new-privileges`·호스트 uid |
| | 4 | 취약한 암호화 알고리즘 사용 | 적용 | 암호화 기능 없음. sha1/md5 는 식별용이며 `usedforsecurity=False` 로 명시 |
| | 5 | 암호화되지 않은 중요정보 | 적용 | LLM 호출은 HTTPS(openai SDK). 전송 전 비밀값 마스킹 |
| | 6 | 하드코드된 중요정보 | 적용 | API 키는 환경변수나 `.env`(gitignore)에서 읽음. 추적 파일은 회귀 테스트로 검사 |
| | 7 | 충분하지 않은 키 길이 | 해당 없음 | 키 생성 없음 |
| | 8 | 적절하지 않은 난수 | 해당 없음 | 보안 용도 난수 없음 |
| | 9 | 취약한 비밀번호 허용 | 해당 없음 | 비밀번호 기능 없음 |
| | 10 | 부적절한 전자서명 확인 | 부분 | 다운로드는 sha256 으로 검증(F08). 서명(cosign 등) 검증은 미적용 |
| | 11 | 부적절한 인증서 유효성 검증 | 적용 | `verify=False` 없음. curl `-fsSL` 기본 검증 |
| | 12 | 쿠키를 통한 정보노출 | 해당 없음 | 쿠키 없음 |
| | 13 | 주석문 안의 시스템 주요정보 | 적용 | 회귀 테스트가 추적 파일의 토큰 형식을 검사 |
| | 14 | 솔트 없이 일방향 해쉬 사용 | 해당 없음 | 비밀번호 해시 없음 |
| | 15 | 무결성 검사 없는 코드 다운로드 | 적용 | Bazelisk sha256 필수, 베이스 이미지 digest 고정(F08) |
| | 16 | 반복된 인증시도 제한 부재 | 해당 없음 | 인증 기능 없음 |
| 시간 및 상태 | 1 | 경쟁조건(TOCTOU) | 부분 | HITL 저장은 락과 병합 쓰기로 처리. 경로 검증은 resolve 후 비교라 다중 사용자 경쟁까지 막으려면 별도 sandbox 가 필요 |
| | 2 | 종료되지 않는 반복문·재귀 | 적용 | 모든 외부 실행에 시간 상한, 타임아웃 시 프로세스 그룹 종료(F05) |
| 에러처리 | 1 | 오류 메시지 정보노출 | 적용 | LLM 프롬프트의 빌드 로그 마스킹. 실행 작업자에 비밀 환경 없음 |
| | 2 | 오류상황 대응 부재 | 적용 | 실행 불가·시간 초과를 예외 대신 실패 결과로 반환 |
| | 3 | 부적절한 예외 처리 | 적용 | 로그·증적 저장 실패를 삼키지 않고 `log_error` 와 경고로 남김(F07) |
| 코드오류 | 1 | Null Pointer 역참조 | 해당 없음(Python) | 하네스는 ASan 으로 검증 |
| | 2 | 부적절한 자원 해제 | 적용 | 출력 버퍼 상한, 컨테이너 `--rm`, 락 fd 정리 |
| | 3 | 해제된 자원 사용 | 해당 없음(Python) | ASan |
| | 4 | 초기화되지 않은 변수 사용 | 해당 없음(Python) | 하네스 대상 결함 유형(MSan 은 현재 미사용) |
| | 5 | 신뢰할 수 없는 데이터의 역직렬화 | 적용 | `pickle`/`yaml.load` 미사용. JSON 만 사용 |
| 캡슐화 | 1 | 잘못된 세션에 의한 정보노출 | 해당 없음 | 세션 없음 |
| | 2 | 제거되지 않은 디버그 코드 | 적용 | `--no-docker` 는 신뢰 대상 디버그 모드로 문서화(아래 운영 가정) |
| | 3 | Public 메서드가 반환하는 Private 배열 | 해당 없음 | Java 계열 항목 |
| | 4 | Private 배열에 Public 데이터 할당 | 해당 없음 | Java 계열 항목 |
| API 오용 | 1 | DNS lookup 에 의존한 보안결정 | 해당 없음 | 없음 |
| | 2 | 취약한 API 사용 | 적용 | Bandit 을 CI 에서 실행(medium 이상이면 실패) |

## 운영 가정

- `--no-docker`(호스트 직접 실행)는 **팀이 직접 고른 신뢰 대상**을 디버그할 때만 쓴다. 외부 제출물에는
  쓰지 않는다. 이 모드에서도 실행 환경은 최소화된다.
- HITL JSON 저장소는 단일 호스트 CLI 용이다. 여러 사용자가 쓰는 서비스로 바꾸면 인증된 승인자와
  트랜잭션 DB 가 필요하다.
- 예외(`# nosec`)는 코드 옆에 사유를 적는다. 새 예외는 리뷰에서 승인받는다.
