# EXE-04-04: Coverage Instrumentation (커버리지 계측)

담당: C(Execute) / 임세은 · 3주차

## 목적
퍼징의 진행도를 exec/s(실행 속도)뿐 아니라 "코드의 어디까지 도달했는가"로
정밀 측정한다. EXE-04-01 격리 실행이 남긴 계측 산출물(`*.profraw`)을 후처리해
함수/라인/리전/브랜치 커버리지를 산출하고, 세션 요약과 SCH-02-03(미탐색 경로
가중치)·ANA 단계가 소비할 형태로 보존한다. 파이프라인상 EXE-04-01/02 실행과
같은 단계에서 동작하며, 실행 흐름 자체는 바꾸지 않는 옵트인 기능이다.

## CLI
```
logosfuzz fuzz --engine <libfuzzer|afl++> --timeout <sec> --docker \
    --harness-dir <dir> --output <dir> --coverage <none|llvm-cov|sancov>
```
`--coverage none`(기본)이면 기존 동작과 완전히 동일하다.

## 3단계 파이프라인
- 계측(빌드): 하네스를 커버리지 플래그로 컴파일해야 한다(GEN/빌드 규약 책임).
  - `llvm-cov`  : `-fprofile-instr-generate -fcoverage-mapping`
  - `sancov`    : `-fsanitize-coverage=trace-pc-guard`
  - 이 계약은 `coverage.instrumentation_flags(mode)` 로 코드에 고정돼 있다.
- 수집(실행): 실행 프로세스에 `LLVM_PROFILE_FILE=/out/coverage/<group>/%m.profraw`
  환경변수를 주입해 profraw를 `/out`(쓰기 마운트)로 떨군다. `%m`은 clang 프로파일
  런타임의 온라인 병합 모드로, 다중 프로세스(AFL++ fork) 환경에서도 안전하다.
- 후처리(실행 후): `llvm-profdata merge -sparse` → `llvm-cov export -format=text`
  로 커버리지 JSON을 얻고, `totals`를 `CoverageSummary`로 정규화한다.

## 구조
- `config.py` : `CoverageMode`(none/llvm-cov/sancov), `FuzzConfig`에 커버리지 필드.
- `execute/coverage.py` : `instrumentation_flags`, `profile_env`,
  `parse_llvm_cov_export`(순수 파서), `CoverageCollector`(merge/export/collect).
- `execute/docker_runner.py` : 컨테이너/호스트 실행 argv에 커버리지 환경변수 주입.
- `execute/fuzz_session.py` : 실행 후 그룹별 커버리지 수집·요약 연결.
- `docker/Dockerfile` : `llvm-cov`/`llvm-profdata`(LLVM 14) 이미 포함(심볼릭 링크).

## 산출물
- `out/coverage/<group>/*.profraw` : 원시 프로파일.
- `out/coverage/<group>.profdata` : 병합 프로파일.
- `out/coverage/<group>.coverage.json` : llvm-cov export 원문(리전/브랜치 상세 보존).
- `out/coverage/<group>.summary.json` : 정규화 요약.
- `out/fuzz_summary.json` : 각 그룹에 `coverage_report` 필드 추가.

## 설계 메모
- 실제 llvm 도구 실행은 `runner` 콜러블로 주입 가능(EXE-04-01의 `executor` 패턴과
  동일) → Docker/llvm 없이도 단위 테스트가 가능하다.
- 기존 libFuzzer `cov:`(엣지 수, 실시간)과 llvm-cov 소스 커버리지(정밀, 실행 후)는
  별개 지표로 공존한다. 전자는 `stats.coverage`, 후자는 `coverage_report`.
