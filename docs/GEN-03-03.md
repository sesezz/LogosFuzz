# GEN-03-03: Mocking 코드 삽입 (팀원 B/D 지원)

담당: C(Execute) / 임세은 · 4주차 · GEN 지원 (하네스 생성 담당 B·D 공통 유틸리티)

## 목적
GEN-03-01/02가 만든 퍼징 하네스는 대상 함수가 호출하는 외부 의존성(하드웨어·
드라이버·다른 모듈 함수)의 정의가 빌드 단위에 없으면 컴파일/링크되지 않거나
실행 즉시 죽는다. GEN-03-03은 "호출되지만 정의가 없는" 심볼을 찾아 컴파일·실행
가능한 mock/stub을 생성하고 하네스에 삽입한다.

## B/D 지원의 의미
팀 4인(A/B/C/D) 중 **B와 D가 모두 GEN(하네스 생성)** 담당이다. 따라서 이 기능은
역할을 나누지 않고 **두 GEN 팀원이 공통으로 쓰는 하네스 생성 유틸리티**로 만들었다.
같은 API(`build_mock_plan` → `insert_mocks`)로 대상/모듈이 달라도 재사용한다.

## 입력 / 출력
- 입력: EXT(AST 분석)의 "정의된 함수"·"호출된 함수" 목록 + 시그니처 문자열.
- 출력:
  - `insert_mocks(harness_src, plan)` : mock이 삽입된 하네스 소스(단일 파일 또는 include).
  - `plan.mock_source()` / `plan.mock_header()` : 별도 컴파일용 mocks.c / 선언부.
  - `plan.manifest()` : 무엇을 어떤 기본값 정책으로 모킹했는지 추적 기록.

## 기본값 반환 정책 (근거)
- 포인터 → `NULL`(호출자 NULL 검사 관례, 쓰레기 포인터 오탐 방지)
- 정수/열거형 → `0`(상태코드 0=성공/중립 관례), 부동소수점 → `0.0`, 불리언 → 0
- 구조체 등 값 반환 → `(T){0}` 제로 초기화
- void → 반환문 없음
- 이름 있는 파라미터는 `(void)p;`로 미사용 경고 제거(-Werror 안전)

## EXE 연계
`strategy="instrumented"`이면 mock 실행 시 `LOGOSFUZZ-MOCK-HIT` 마커를 stderr로
출력한다. EXE-04-02 sanitizer가 이 문자열을 `mocking-fail-fp`로 분류하므로,
크래시가 실제 결함인지 모킹 부작용인지 ANA가 구분할 수 있다. 남용 시 로그 오탐이
생기므로 기본은 `buildable`(마커 OFF).

## 파일
- `logosfuzz/generate/gen_03_03_mock_injector.py` : 시그니처 파서, 기본값 정책, stub 생성, 후보 탐지,
  계획 수립(`build_mock_plan`), 코드 삽입(`insert_mocks`). 표준 라이브러리만 사용.
- `tests/test_gen_03_03_mock_injector.py` : 파서·정책·탐지·생성·삽입 11개 테스트.

## 검증
- `pytest` 전체 59 passed.
- 생성된 mock 삽입 하네스를 `cc -std=c11 -Wall -Wextra -Werror`로 컴파일/링크/실행
  성공(미정의 심볼이 mock으로 해소됨).
