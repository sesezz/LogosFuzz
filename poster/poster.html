01

배경과 목표

왜 필요한가

  • 공급망 위험: 라이브러리 하나의 결함이 SW 전체로 확산 (Heartbleed, BadAlloc, Redis)
  • 높은 진입장벽: OSS-Fuzz가 1,000개 프로젝트에서 10,000건+ 발견했지만 수작업 하네스 필요
  • 규제: 자동차·SDV는 UN R155(CSMS) 준수 의무

기존 방식의 한계

  • 수작업: 프로젝트당 수 시간과 전문지식
  • 구조 복원 실패: score/json 106개 파일에서 API 0개 추출
  • 환경 의존 오류: 하드웨어·외부 함수 부재로 링크 실패와 가짜 크래시

개발 목표

“프로필 1개 설정, 명령어 한 줄로 지식 추출부터 크래시 판별까지”
$ logosfuzz run --profile

기대효과 · 향후 계획

기대효과

  • 하네스 작성 자동화: 프로필 1회 작성으로 수작업 대체
  • 탐지 범위 확대: 하드웨어 없이 임베디드 코드 탐색
  • 공급망 검증: 도입 전 보안 검증, UN R155 증거 축적

향후 계획

  • 기술 고도화: ASan 크래시 위치 복원, 누락 로직 그룹 보완
  • 검증 자동화: GitHub Actions 연동 CI 보안 검증
  • 범위 확대: 바이너리 대상 퍼징, 다양한 CPU 아키텍처
